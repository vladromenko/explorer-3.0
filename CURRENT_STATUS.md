# Explorer 3.0 — актуальное состояние

14 ноября 2026. Текущий объём: завершение программной подготовки к сбору данных
и ограниченного агентного слоя. Разрешены короткие программные проверки и
браузер. Новые вызовы моделей, симуляционные прогоны, обучение и реальные
движения не выполнялись. Предыдущий общий запрет тестов уточнён оператором.

## Программная поставка

- Существующий Explorer :8030 сохранён. Есть отдельные реальные задачи SO-101,
  ROSMASTER-рука, ROSMASTER-база, Tank; записи, исходные датчики, просмотр,
  проверка данных и подготовка неизменяемого плана обучения. Старые :8020,
  :8090, WristLab и заводские проекты не изменялись.
- Официальные ACT/SmolVLA/Diffusion и симуляционные PPO/Playground остаются
  отдельными рецептами. Для RGB/depth/lidar/IMU используется явный профиль
  с дополнительным входом ACT; SmolVLA не получает эти каналы молча.
- Локальные Qwen3-VL-2B, YOLOE и SAM3 уже скачаны: контрольные суммы проверены.
  Один Qwen-worker используется шестью логическими ролями, а не шестью LLM.
  Добавлены исходные кадры в VLM, YOLOE/SAM3 с evidence и ByteTrack одной камеры.
  Прямой VLM тракт прошёл processor-only проверку; новую генерацию не запускали.
- Координатор предлагает только зарегистрированные испытания. Исполнитель
  использует существующие контроллеры/запись, отдельный физический допуск,
  поколения STOP и пульс браузера. Следующий шаг требует сохранённого результата
  и явного подтверждения. План модели сам не включает моторы.
- Общая память сохраняет происхождение, отрицательные случаи и область
  совместимости. Перенос к другой платформе создаёт новую гипотезу и связь
  donor episode → source case → recipient episode; не копирует суставные
  команды и не объявляет пользу по одному успешному повтору.
- Сравнение M0–M3 фиксирует одну память, варианты, бюджеты, версии и seeds.
  Неполные/неизвестные исходы остаются в отчёте. G используется только при
  подходящем артефакте; без него доступен фиксированный выбор по измерениям.
- S2 использует существующие ограниченные ветви восстановления и геометрические
  эксперты четырёх сред. Это симуляционный privileged baseline. Физическая
  передача между напольным роботом и настольной рукой не объявляется возможной.
- R4 реализован как **DART-inspired**, без оптимизации ковариации полного DART:
  масштаб из validation-ошибки ACT, одинаковые ограниченные пары seeds,
  отдельные expert intent / executed action / response, просмотр перед импортом.
  Этот режим не меняет реальные записи и не запускает обучение.
- Тяжёлые задания исключаются во время ручного управления. Ручное управление
  разными роботами может существовать параллельно. После STOP новый запуск
  требует нового допуска, запоздавшая команда включения отклоняется.

## Что проверено сейчас

`validation/dataset-release-20261114/` в хранилище Explorer:

- `final-software-tests.xml`: 92 PASS, 2 subtests PASS; 2 теста с модельным forward
  намеренно исключены. Фикстуры проверяют контракты, не физику.
- Три браузерных пути: план обучения/сброс подтверждения, настоящие записи и
  инструкция, кадры/сравнение/миссия/отказ восстановления без baseline.
  Нет внешних запросов, ошибок страницы, новых jobs или моторных команд.
- Пять прежних реальных успешных записей прочитаны: SO-101 — 3, ROSMASTER-база — 1,
  Tank — 1. Это не основной обучающий набор. Записи aborted не переименованы.
- Контрольные суммы локальных моделей; настоящий processor без весов/генерации;
  upstream ByteTrack на числовой фикстуре без нейросетевого inference.
- Read-only проверка обоих устройств: собственные agent/driver/sensor файлы
  совпадают с текущими файлами репозитория. Датчики ROSMASTER и Tank отвечали.
  Команды движения, захват управления и установка чужих служб не выполнялись.

Новый physical TaskGraph, прямое VLM понимание кадра, R4 и перенос памяти
не объявлены принятыми на железе или научно результативными. Запуски моделей
и симуляционные прогоны новой версии остаются отложенными по указанию оператора.
Исторический S1 Qwen → общий MuJoCo → отдельные исходы → память сохранён,
но не подменяет новую приёмку после изменения кода/геометрии.

## Аппаратные зависимости

**Tank: независимая остановка при разрыве USB не обеспечена подтверждённым
механизмом на моторном контроллере.** Ранее EIO не позволил доставить STOP.
В установленном SDK не найден документированный MCU command timeout.
Pi-watchdog не исправляет разрыв его связи с моторной платой. Incident-block
сохранён; обычное движение и сбор Tank заблокированы до отдельного решения
и стендовой приёмки. Прошивка, порог питания и зуммер не изменены.
Писк исчез после исправления зарядного провода по сообщению оператора.

ROSMASTER: прежнее управление/направления/STOP приняты оператором; после
обновления нужен короткий повтор и реальные показы расширенных профилей.
USB-микрофон/RGB имеют существующие интерфейсы, физическая проверка не завершена.
OLED подключён к MCU; в документированном текущем API команды вывода нет.
Неподдержанный дисплей не имитируется и не блокирует сбор движений/датчиков.

SO-101: сохранены принятые показы и калибровки; нужен короткий показ после
обновления. SO стоит на столе, обе мобильные платформы на полу.

ROS 2: собственный read-only hub Homebrain и раздельные домены 0/30/73,
MCAP и общий просмотр реализованы. Общая метрическая карта требует измеренной
калибровки; часы, локальные frame IDs и отсутствие общей TF показаны явно.
Динамика Tank, скольжение и физические размеры общей установки не откалиброваны.

## Конечная приёмка и сбор

[Только оставшиеся физические проверки](docs/PHYSICAL_ACCEPTANCE_RU.md).
[Инструкция по формированию датасета](docs/DATASET_GUIDE_RU.md).
[Аудит всех трёх заданий](docs/AGENT_CONTRACTS.md).

Сначала ROSMASTER отдельно, затем Tank после устранения границы STOP/USB,
затем SO-101; общий аппаратный блок — после независимых допусков. Не требуется
держать все машины включёнными. Основной рецепт: минимум 50 пригодных показов
одной задачи и минимум 3 независимые группы; это технический порог, не гарантия
обученного навыка. Пробные три записи проверяют тракт; обучение запускает
оператор после отдельного разрешения. Версия работающего интерфейса доступна
в `/api/health` → `process_build` и `startup_source_sha256`.
