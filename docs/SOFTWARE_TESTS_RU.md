# Программные проверки перед записью

Из корня проекта: `./scripts/run_all_tests.sh`. Можно запустить одну группу:
`--group main`, `--group sim`, `--group browser`.

Все `tests/test_*.py` распределяются по группам в `conftest.py`. Число файлов
вычисляется из текущего дерева, а не из устаревающего числа в задании.
Основные тесты используют `.venv`; симуляционные регрессии — `.venv-sim`, EGL
и копии уже установленных исходных геометрий. Обучение и генерация моделей
не запускаются: соответствующие существующие тесты имеют явный skip с причиной.
Число пропусков выводится отдельно, это не успешные проверки.

Браузерное окружение устанавливается один раз:

```sh
python3 -m venv .venv-browser
.venv-browser/bin/pip install -r configs/browser-test-requirements.txt
.venv-browser/bin/python -m playwright install chromium
```

Браузер открывает только временное приложение на `127.0.0.1:8037`; занятый
порт означает ошибку, чужой сервер не завершается. В нём нет контроллеров
роботов, фонового исполнителя заданий и автоматического запуска моделей.
Рабочая служба :8030 не перезапускается. Каждый запуск использует отдельный
`EXPLORER3_DATA`; журналы и JUnit XML сохраняются в `validation/tests-<UTC>/`,
сводный JSON — `validation/tests-<UTC>.json` в каталоге данных Explorer.

Аппаратная приёмка не входит в эти результаты. Программный PASS не означает,
что робот физически остановился или датчик правильно измеряет расстояние.
