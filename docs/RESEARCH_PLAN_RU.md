## 1. Вопрос статьи

**Может ли робот сам понять, каких знаний ему не хватает для задачи, и закрыть этот пробел с помощью роя —
других роботов, симуляции, более сильной модели? И сколько тогда нужно собственных показов человека?**

Роботы: **ROSMASTER** (получатель: колёса + рука, камера на руке), **SO-101** (стенд на столе: камера сверху,
измеряет предметы, даёт опыт захвата), **Tank** (разведчик: ищет предметы на общей карте),
**Homebrain** (вычисления: обучение, крупные модели).

Четыре вида пробелов и кто их закрывает:

| Пробел | Робот спрашивает себя | Кто помогает |
|---|---|---|
| ГДЕ | Знаю ли я, где предмет? | Tank / собственный поиск |
| ЧТО | Узнаю ли я этот предмет? | Сильная модель на Homebrain (SAM3) вместо быстрого YOLOE |
| КАК | Знаю ли я размеры и как брать? | SO-101 (измерение) |
| НАВЫК | Есть ли у меня обученный захват этого предмета? | Симуляция, опыт SO-101, показы человека |

### E5 подробно — варианты обучения
- **T0** — только собственные показы ROSMASTER.
- **T1** — предобучение на 200 показах MuJoCo + собственные показы.
- **T2** — T1 + опыт SO-101, перенесённый в механику ROSMASTER (MimicGen-адаптация, своя IK ROSMASTER).

Для каждого варианта k = 0/5/10/20 собственных показов. Одинаковые исходные веса, число обновлений, сенсоры.
- Без робота: все 12 моделей оцениваются на **5 отложенных** реальных показах (ошибка действий) — полная кривая.
- На роботе: k = 20 для T0, T1, T2 — по 10 попыток (≈1 ч с владельцем).

Ожидаемая картинка:
```
успех │            ● T2/T1 (с помощью роя)
      │        ●        ○ T0 (без помощи)
      │    ●       ○
      │●      ○
      └──────────────────── своих показов
       0   5   10      20
```
Если кривая с помощью выше, рой экономит показы человека; разница по оси k — ответ «сколько».
Отрицательный результат публикуется так же.

### E6 подробно — как проверяем «понимает, чего не знает»
| Ситуация | Правильный ответ робота |
|---|---|
| Предмет, на котором обучен (кубик) | «знаю, беру сам» |
| Предмет, которого не было в обучении этой модели (паста при модели без пасты) | «нет навыка → зову помощь» |
| Новый предмет, который никогда не записывали | «не узнаю / не знаю → помощь или человек» |
Измеряем: доля верных решений, ложные «знаю» (опасно) и ложные «не знаю» (лишняя помощь).

Правила записи ROSMASTER (важно для статьи):
1. **Одна серия = один предмет**, название одним английским словом: `cube`, `candy`, `toothpaste`.
2. **Перед «Записью» предмет целиком виден в камере руки** — детектор находит его на первом кадре (E3/E4).
3. Каждый показ — новое место и поворот, 16–26 см перед роботом; колёсами не ездить.
4. Опуститься, сжать, поднять ≥5 см, держать 1–2 с. Неудачи — F11, не удалять.

Не делаем (вне дедлайна): блок 4 «передача человеку» (50 показов SO-101), места передачи, датасет Tank,
обучение по видео с телефона (раздел «дальнейшая работа»).

## 7. Решения после независимого ревью (20.11.2026)

Ревью: `Explorer_3_Review_RU_2026-11-20.pdf` (66 работ). Главное замечание: заявленный вклад шире измеряемого.
Принятые изменения (вариант A ревью — честный пилот, 30–45 физических попыток):

1. **Один основной предмет для моторной политики — кубик.** Конфета и паста остаются для распознавания (E4)
   и отказа от действия (E6): «кубик знаю — беру; конфету/пасту бортовой детектор не узнаёт — зову SAM 3».
2. **Главная метрика E5 — автономный успех на роботе**, не офлайн-ошибка (она только диагностика по фазам).
   Сравнение: T0 и T1 при k = 5 и k = 20, по 10 одинаковых заранее заданных сцен, блоки перемешаны (40 попыток).
   Вложенные наборы: k=5 — заранее выбранное подмножество k=20, одинаковое для всех методов.
   T2 (донор SO-101) — предварительный результат, пока нет проверенного пакета, воспроизводимого в механике ROSMASTER;
   при выводе о доноре обязателен контроль равным объёмом синтетических данных собственного учителя.
3. **Статистика:** парная таблица исходов, разность долей с интервалом, честно указанная мощность.
   Один первичный контраст (T1 vs T0 при k=5); остальное — exploratory. Критерий E3+ исправлен: парный тест на
   новых заранее зафиксированных seeds (старые 10000–10019 стали диагностическими).
4. **E6 — shadow mode на попытках E5:** до каждой попытки сохраняется решение «беру / нужна помощь», затем
   сравнивается с исходом. Метрики: coverage, selective risk, risk-coverage. Нет заявлений о гарантиях.
   Плюс случаи «знакомый, но трудный» (край досягаемости) и «новый, но выполнимый».
5. **E3 — сначала диагностика, потом новые модели:** replay записанных команд в MuJoCo; overfit 3–5 сцен;
   проверка семантики данных (камера, порядок суставов, единицы, клешня, нормировка); сравнение горизонта
   исполнения 1/5/10/100 на готовом checkpoint; ошибки по фазам на всех 20 сценах.
6. **E1:** добавить «лучший фиксированный помощник», «случайный помощник», «всегда все», oracle; новые 100+ комнат.
7. **E2:** формулировка «носок — низкая надёжность этого контроллера» (а не «не берётся»); факторный размер × yaw.
8. **E4:** заранее зафиксированные промпты и синонимы, 10–20 кадров без цели и с похожими предметами,
   сравнение YOLOE-only / SAM-always / selective; разметка не той же моделью.
9. Проверено 20.11: в поле action пишется команда **после IK и ограничений** (arm_target в силе на следующем
   снимке агента); намерение Leader и фактически отправленная команда пишутся отдельно.
10. Вырезано до дедлайна: сравнение архитектур (ACT/SmolVLA/Diffusion/π0), видео с телефона, Tank-задачи,
    передача человеку, LLM-диспетчер как основной метод.

Рабочее название: *Explorer 3.0: Selective Knowledge Reuse for Data-Efficient Learning in Heterogeneous Robot Teams*
(если экономия не подтвердится — *An Empirical Study of Knowledge Reuse in Low-Cost Heterogeneous Robots*).
