# Explorer 3.0 — техническая готовность к записи датасета

Дата: 14 ноября 2026. Исполнитель: агент на Homebrain (Jetson Orin NX),
репозиторий `~/Projects/explorer-3.0`, UI :8030, данные `~/.local/share/explorer3`.

## 0. Цель и как понять, что готово

Пользователь утром:
1. включает Homebrain, ROSMASTER, Tank, подключает SO-101;
2. открывает одну страницу Explorer «Готовность»: всё зелёное, а у красного
   написано, что сделать;
3. за 10–15 минут на робота проходит короткую проверку «всё ездит»: каждое
   направление, отпускание, STOP;
4. открывает «Сбор датасета», выбирает задачу и пишет показы подряд. Имена
   серий, счётчики, проверка каждой записи — автоматически.

Без вмешательства агента, ручных команд в терминале, правки JSON-файлов и
чтения журналов. Этот документ — единственное задание. Исследовательская
часть (`SOFTWARE_AUTONOMY_PROMPT_RU.md`, рамка автономности, анализ,
симуляция) — **после** записи датасета, здесь не делается.

**Tank ездит по полу.** Решение пользователя 14.11.2026: управление Tank
исправлено после USB-инцидента 13.11 (включая зарядный провод), блокировку
снять, езду по полу разрешить и настроить. Защиты, которые работают
автоматически, сохраняются и усиливаются (раздел R2). Отдельная стендовая
приёмка как условие **не требуется**.

## 1. Ограничения

- SO-101/WristLab :8020 и Console :8090: код, службы, данные не менять.
  Остановка и запуск :8020 — только действием пользователя (кнопка с
  подтверждением в R4 или вручную), не агентом самостоятельно.
- Агент не отправляет команды движения сам. Всё движение — пользователь из
  UI. Агенту разрешено:
  - SSH-чтение;
  - установка своих файлов агента на роботов;
  - перезапуск своих служб `explorer3-*`;
  - снятие блокировок Tank по R2.1 (решение пользователя выше).
- Обучение, fine-tune, генерацию моделей не запускать.
- Прошивку плат не менять. Штатные пакеты производителей не править
  (только запуск и остановка штатным способом).
- UI :8030 не перезапускать при активном управлении или записи.
  Проверки — в изолированном UI на 8035–8039 с временным `EXPLORER3_DATA`.
  Без широких `pkill`.
- Git: только свои законченные изменения, проверенный diff, без force-push. Пуш:
  `GH=~/.local/share/explorer3/tools/gh_2.103.3_linux_arm64/bin/gh; GIT_TERMINAL_PROMPT=0 git -c credential.helper= -c credential.helper="!$GH auth git-credential" push -q origin main`.
- Не коммитить секреты, калибровки, веса, видео, материалы производителей.

### 2.2. Tank
- MentorPi T1, Raspberry Pi 5, плата RRC Lite (`/dev/ttyACM0`, USB `1a86:55d4`,
  1 Мбод). Агент `explorer3-tank-agent.service` (docker exec в контейнер
  MentorPi, `/home/ubuntu/explorer3`) и два наблюдателя сенсоров работают;
  при старте агент инертен.
- **Скорость ограничивает только UI.** `motion_permission.limited_command`
  без блокировки и без режима подставки возвращает `v, w` **без ограничений**.
  Ограничение 0.2 м/с и 0.5 рад/с (`BENCH_V/W`) подставляет
  `explorer3/control.py:127` для клавиатуры. Команды политики (ACT) и любой
  другой источник сейчас агентом не ограничиваются.
- Плавного разгона нет: ступенька от 0 до максимума. Связь USB-отказов
  13.11 с бросками тока при старте моторов **не доказана**, но плавный
  разгон дёшев и снижает этот риск.
- При отказе USB агент пишет `incident-block.json` навсегда; снять его может
  только человек через агента. Для повседневной работы это слишком тяжело.
- Плата по SDK отдаёт напряжение, IMU, кнопки, геймпад, SBUS. **Энкодеров
  нет.** Измерить движение можно по IMU и лидару.
- Нагрузка Pi в режиме наблюдения: load average около 5.3–5.6.
- Инструкция Hiwonder (локальная копия
  `~/.local/share/explorer3/cache/references/mentorpi-t1-complete/`):
  - **глава 3.4** — нулевая команда обязательна, закрытие программы
    может не остановить шасси; рекомендованные пределы |v| ≤ 0.6 м/с,
    |ω| ≤ 2 рад/с; управление через `/controller/cmd_vel`;
  - **глава 3.2** — калибровка IMU, линейной и угловой скорости
    (`imu_calib.yaml`, `calibrate_params.yaml`), если уводит в сторону;
  - **глава 3.3** — `/imu` через `imu_filter.launch.py`; EKF;
  - **глава 1.3** — заряжать ниже 6.4 В, только выключенным, штатным
    зарядником 8.4 В 2 А; плата использует порог 6.9 В;
  - **глава 1.3.4** — геймпады нескольких роботов мешают друг другу;
  - **глава 1.5** — загрузка около 1 мин, затем сигнал готовности.

### R6. Страница «Сбор датасета»
1. Выбор задачи (4 профиля и варианты). Для баз по умолчанию
   `*_rgbd_lidar`, для рук — обычный. Смешивать варианты в одной задаче
   нельзя: UI не даёт.
2. **Серии без ручного ввода имён:** кнопка «Новая серия» создаёт
   `<задача>-s<NN>` и расстановку `<задача>-layout<NN>`. Можно указать, что
   расстановка повторяет прежнюю: тогда группа общая, и UI так и пишет.
   Короткое поле «что изменилось в расстановке».
3. Счётчики:
   - успешные / неуспешные / прерванные в серии и всего;
   - «до 50: N»;
   - независимых групп;
   - цель 10 серий × 5;
   - средняя длительность;
   - место на диске на оставшиеся показы.
4. Один показ: «Начать» → индикатор растущих кадров по каждому потоку →
   «Успех» / «Неуспех» / «Прервать».
   - После сохранения **автоматически**: чтение записи обратно, проверка
     потоков (нет пропусков больше 200 мс, кадры совпадают с действиями,
     длительность в пределах 3–120 с), миниатюра первого и последнего кадра.
   - Проблема — жёлтая плашка с причиной и кнопкой «Исключить из обучения»
     (без удаления).
   - Следующий «Начать» доступен сразу после сохранения.
5. Горячие клавиши: «Начать / Успех / Неуспех» — отдельные от клавиш
   движения. STOP остаётся пробелом и всегда приоритетнее.
6. В метаданные эпизода: оператор, серия, расстановка, описание изменения,
   напряжение в начале и минимальное, отказы связи, версия агента, профиль,
   пределы скорости.
7. После каждой серии — экран «Посмотрите 1–2 записи» с плеером.

### R7. Сохранность данных
- Ежедневная резервная копия каталога SQLite (`sqlite3 .backup`, в
  Python — `sqlite3.Connection.backup`) и манифест хешей эпизодов.
- Опция копирования новых эпизодов на внешний диск, если подключён (путь
  задаёт пользователь).
- Защита: запись не начинается при свободном месте ниже 8 ГБ; при
  заполнении во время записи — корректное завершение эпизода.
- Тест: резервная копия восстанавливается, хеши совпадают.

### R8. Проверка «всё ездит» (её проходит пользователь)
Пошаговый мастер в UI для каждого робота, около 10 минут. Каждый шаг:
что сделать → автоматическая проверка по датчикам → PASS/FAIL.
Результат — в `validation/physical/<робот>-<дата>.json`.
- **Tank:**
  - зарядник отключён (напряжение ниже 8.3 В и не растёт);
  - вперёд, назад, влево, вправо по 2 с;
  - отпускание → ноль;
  - STOP во время движения;
  - «едет прямо?» (R2.7);
  - лидар-стоп перед коробкой;
  - скрытие вкладки → стоп;
  - камера и лидар видят сцену.
- **ROSMASTER:** то же для базы; суставы и захват небольшими шагами;
  датчики; STOP.
- **SO-101:** взять у :8020 (R4), Leader → follower, захват, STOP, скрытие
  вкладки.
- В конце — одна пробная запись по задаче с автоматической проверкой (R6.4).

FAIL не блокирует навсегда: показывается причина и что сделать.
