## A. Рамка исследования: от «когда звать человека» к полной автономии

### A.1. Вопрос статьи
Прежняя рамка: оценить пользу человеческой помощи и перенести эту оценку между
роботами. Человек в ней — постоянная часть контура. Новая рамка:

> **Как довести неоднородный парк роботов (рука SO-101, гусеничный Tank,
> мобильный манипулятор ROSMASTER) до работы без человека и насколько
> перенос знаний между роботами и из симуляции сокращает человеческий труд,
> нужный для этого.**

Человек остаётся только в трёх ролях:
1. автор исходных показов;
2. источник истинных меток для проверки автоматических детекторов (на
   отложенной выборке);
3. аварийная остановка.

Итоговая оценка — **ноль вмешательств человека** на фиксированном наборе
стартовых условий.

### A.2. Компоненты автономности (каждый — измеримый модуль)
1. **Детектор успеха** по задаче: закончена ли задача, без человека.
2. **Монитор сбоя**: предсказывает срыв до него (риск-признаки,
   AutoIntervene-adapted уже есть).
3. **Восстановление без человека**: повтор с исходной позы, политика
   восстановления, программный резерв (захват по восприятию; Nav2 для баз).
4. **Автономный сброс сцены**: робот сам возвращает задачу в стартовое
   условие. Без этого нет ни автономной оценки, ни автономной практики.
5. **Автономная практика**: прогоны → проверенные успехи → дообучение →
   новая версия. Это само обучение здесь **не запускается**, нужен только
   конвейер подготовки.
6. **Оболочка безопасности** для работы без присмотра.

### A.3. Гипотезы (уточняются и фиксируются в предрегистрации, S12)
- **A1 (восстановление).** На одинаковых стартовых условиях «политика +
  монитор + восстановление» даёт больший процент автономного успеха, чем одна
  политика. Сравнение парное, по стартовым условиям.
- **A2 (практика).** Раунды автономной практики, где успехи отбирает детектор,
  повышают автономный успех без новых человеческих показов. Кривая: процент
  успеха и секунды человека на раунд.
- **A3 (перенос).** Монитор, детектор успеха и восстановление, перенесённые с
  робота-источника (SO-101 → рука ROSMASTER; Tank → база ROSMASTER) и из sim,
  уменьшают человеческие секунды до заданного уровня автономности на
  целевом роботе. Сравнение с обучением только на целевом роботе.
  Отрицательный контроль — перенос с «чужого» робота.
- Причинный аппарат v3 (рандомизация, DR-оценка, CATE) используется без
  изменений формул. Теперь он выбирает **способ автоматического
  восстановления** в момент обнаруженного сбоя. Вариант «звать человека» —
  только как дорогой эталон.

### A.4. Метрики (во всех отчётах одинаковые)
- `autonomous_success_rate`: доля попыток, завершённых успешно без человека
  (успех подтверждает человек на отложенной части, а не только детектор).
- `MTBI`: среднее время работы между вмешательствами человека; `interventions_per_hour`.
- `human_seconds_per_success`: показы + коррекции + разметка + сбросы руками.
- `autonomous_reset_rate`: доля успешных автоматических сбросов.
- Детектор успеха: точность, полнота, **доля ложных успехов** (критично: ложный
  успех загрязняет данные практики). Порог для использования — не более 5 %
  ложных успехов на отложенной разметке.
- Безопасность: число срабатываний оболочки, число аварийных остановок
  человеком (должно стремиться к нулю).

### A.5. Позиционирование (проверить каждую ссылку перед текстом статьи)
- Близкие работы:
  - Sirius (Liu et al., 2022) и Fleet-DAgger (Hoque et al., 2022) —
    сокращение участия человека;
  - ThriftyDAgger (Hoque et al., 2021);
  - SOAR (Zhou et al., 2024) — автономное улучшение с детектором успеха на
    базовой модели;
  - RoboCat (Bousmalis et al., 2023) — самоулучшение;
  - reset-free RL (Gupta et al., 2021; Sharma et al., MEDAL);
  - VLM как детектор успеха (Du et al., 2023);
  - RESCUE, FARM, AutoIntervene — из аудита.
- Новизна, которую реально можно защитить: **неоднородный парк**, перенос
  компонентов автономности между разными телами и из sim, честная цена в
  человеческих секундах. «Полная автономия» не утверждается, если её нет:
  публикуется измеренный уровень.

### A.6. Честные ожидания
Политики ACT на 50 показах на Jetson вряд ли сразу дадут высокий процент
успеха. Поэтому статья держится на **приросте** автономности и **снижении**
человеческого труда, а не на 100 %. Любой компонент, не прошедший проверку
(например, детектор с ложными успехами больше 5 %), подаётся как отрицательный
результат, а не прячется.

### S6. Автономный сброс сцены
1. Руки: программа сброса.
   - Взять кубик из коробки по восприятию (S5).
   - Положить в случайную позицию из набора допустимых стартовых позиций
     расстановки; набор задаётся пользователем один раз, в координатах стола.
   - Отвести руку.
   - Проверка сброса тем же детектором (кубик вне коробки, в зоне старта).
2. Базы: отъезд от цели в случайную стартовую позу из набора (расстояние,
   угол). Сначала — замкнутый цикл по IMU и лидару с ограничением скорости
   (S2.1), позже — Nav2 (S2.9).
3. Неудачный сброс: две попытки, затем пауза и запрос человека. Это
   отдельный учёт: `human_seconds` типа `reset`.
4. Все сбросы идут через исполнитель с `command_source='reset'` и
   записываются (данные сброса тоже пригодятся).

**Тесты:** фейковый робот; выбор стартовой позы воспроизводим по seed;
ограничения рабочей зоны соблюдаются.
**Коммит:** `Scripted autonomous scene reset for arms and bases`.
