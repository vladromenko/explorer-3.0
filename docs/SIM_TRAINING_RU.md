# Обучение в MuJoCo с переносом на роботов (simlab)

Код: `explorer3/simlab/`. Промпт этапа: `docs/handoffs/SIM_TRAINING_PROMPT_RU.md`.
Состояние на 14.11.2026 — внизу, в разделе «Статус».

## Как устроено

| Часть | Файл | Что делает |
|---|---|---|
| Контракт наблюдений | `simlab/contract.py` | Одинаковый вектор признаков в симуляции, теневом режиме и на роботе. Базы: цель по метке (дистанция, пеленг, угол, видимость, возраст), 36 секторов лидара, гироскоп z и ускорения x/y, предыдущее действие. Версия и хеш хранятся в политике; несовпадение → отказ загрузки |
| Сцена и сценарии | `configs/scene_measurements.yaml`, `configs/scenarios/dock_v1.yaml`, `simlab/scenario.py` | Размеры из ваших замеров (`docs/SCENE_MEASUREMENT_RU.md`), распределения стартов, препятствия, помехи, замороженный набор оценки |
| Обучение баз | `simlab/dock_gpu.py` | Тысячи сред на GPU. Привод: задержка, мёртвая зона, инерция, проскальзывание. Слой агента робота: ограничения, плавный разгон, стоп по лидару (как на настоящих Tank и ROSMASTER). Лидар — трассировка лучей, метка — поле зрения, перекрытие, шум, пропуски |
| Проверка баз | `simlab/dock_mujoco.py`, `scripts/simlab_eval.py` | Полная MuJoCo: модель шасси производителя, контакты, лидар `mj_multiRay`. Решение о допуске — только по ней |
| Обучение рук | `simlab/arm_warp.py` | SO-101 и рука ROSMASTER на MuJoCo Warp (GPU), контакты кубика и коробки, шаг управления в CUDA graph |
| Учитель рук | `simlab/arm_demos.py` | Показы скриптового учителя `sim/expert.py` в формате контракта, для клонирования и старта PPO |
| PPO | `simlab/ppo.py` | Асимметричный: актор видит только признаки робота, критик — точное состояние симуляции. Учебная программа: усложнение при успехе выше 70 % |
| Идентификация | `simlab/sysid_base.py`, `scripts/simlab_sysid.py` | Задержка, инерция, усиление, мёртвая зона по записям «+ глубина и лидар». Принимается, только если на отложенной части ошибка падает больше чем на 10 %; тогда среда обучения берёт найденные диапазоны |
| Восприятие | `simlab/perception.py` | ArUco-метка цели → признаки контракта (неоднозначность позы снята; метка не меньше 15 см). Кубик по цвету и плоскости стола |
| Политика | `simlab/artifact.py` | `policy.npz` + `policy.json`: веса, нормировка, контракт, хеш сцены. Исполнение — только numpy (работает в любом окружении и на Pi у Tank) |
| Теневой режим | `scripts/simlab_shadow.py` | Политика проходит реальную запись кадр за кадром; команды не отправляются; отчёт о совпадении с оператором, выходе за распределение, задержке |
| Запуск на роботах | `simlab/runtime.py` | Цикл на робота, все параллельно; режимы «тень» и «оператор рядом»; любая ошибка или превышение задержки → остановка робота |

## Команды
```bash
# пробный прогон (до 15 мин); полное обучение — только после явного «запускай»
PYTHONPATH=. .venv-sim/bin/python scripts/simlab_train.py tank --minutes 10
PYTHONPATH=. .venv-sim/bin/python scripts/simlab_train.py so101 --minutes 12 --demos 200
# оценка в полной MuJoCo на замороженных стартах
MUJOCO_GL=egl PYTHONPATH=. .venv-sim/bin/python scripts/simlab_eval.py ~/.local/share/explorer3/simlab/policies/<имя>
# идентификация привода по реальным записям с лидаром
PYTHONPATH=. .venv-sim/bin/python scripts/simlab_sysid.py tank <папка записи> ...
# теневой режим на реальной записи (основное окружение)
PYTHONPATH=. .venv/bin/python scripts/simlab_shadow.py <политика> <папка записи>
```

## Порог допуска политики к роботу
- Успех в полной MuJoCo не меньше 80 % на замороженном наборе и не меньше 60 % на
  динамике, изменённой сильнее, чем при обучении.
- В теневом режиме на реальных записях нет действий за пределами.
- Задержка меньше половины периода управления.

## Статус (14.11.2026)
- Вычислительный бюджет: `docs/COMPUTE_BUDGET.md`.
- **Базы.** Весь конвейер собран и проверен. Пробные прогоны по 10 минут:
  - Tank — 73 % успеха на учебной программе 0.5; в полной MuJoCo 74 %
    (95 % ДИ 60–84 %) на тех же условиях;
  - ROSMASTER — 74 % на программе 0.1.
  До полной программы и порога 80 % нужны полные запуски обучения.
- **Руки.** Среды SO-101 и руки ROSMASTER на GPU работают. PPO с нуля за пробный
  прогон не учится. Клонирование учителя пока не даёт успехов: исправлены отсутствие
  времени в признаках и накопление ошибок в приращениях (действие теперь —
  абсолютная целевая поза), идёт проверка.
- **Не сделано:**
  - идентификация по реальным логам — нужны записи «+ глубина и лидар»;
  - замеры сцены (`status: assumed`);
  - страница «Политики парка» в UI;
  - экспорт политик рук в numpy-формат.
