# Единый допуск парка

Рабочий документ — `~/.local/share/explorer3/configs/fleet.json`.
`configs/fleet.json` в репозитории — образец принятого решения. Наличие файла
не открывает устройства: запуск остаётся явным действием пользователя, TTL,
STOP, блокировка занятых портов и проверки измерений сохраняются.

`fleet_config.robot_allowed(robot)` — общий источник допуска управления,
камер, Leader и удалённых клиентов. Отсутствующий/повреждённый файл запрещает
доступ с объяснением. Старые workflow/stage/hardware-enabled флаги не дают
разрешений и не могут перекрыть новое решение. Допуски конкретного испытания
политики остаются отдельным подтверждением запуска конкретного плана.

SO-101 при миграции остаётся у `legacy_8020`: никакая служба не останавливается.
Передача владельца выполняется отдельной кнопкой пользователем (пакет R4).
Изменение владельца вручную в JSON не заменяет освобождение устройств.

Миграция: `.venv/bin/python scripts/migrate_permissions.py`.
Сначала создаётся архив `archive/permissions-<UTC>-<id>/` с исходными файлами,
SHA256 и README.json. Создаётся fleet.json; прежние допуски удаляются только
после проверки сохранённой копии. Повторный вызов сохраняет текущие решения.
Во время активного управления или записи миграция запрещена блокировкой.

Откат: тот же скрипт с `--rollback <полный путь архива>`.
Он проверяет контрольные суммы и откажется затирать изменённый после миграции
fleet.json или старый файл. История инцидентов и отчёты сохраняются. Ключи,
токены, калибровки, датасеты и настройки служб не участвуют в миграции.
