# Tank — готовность к записи, R0–R9 (14.11.2026)

По принятому пользователем заданию езда по полу разрешена. Старые файлы
блокировки архивированы на Homebrain и Tank с контрольными суммами. Это решение
о допуске, а не доказательство аппаратного устранения USB-инцидента.

Собственный агент установлен с резервной копией и проверкой исходных хешей;
после запуска `armed=false`, `hardware_open=false`. Обучение и реальные команды
движения агент не запускал. Новый программный цикл требует физической проверки
оператором в мастере R8; отдельная приёмка на подставке не является допуском.

Открыть: [готовность](http://192.168.0.168:8030/recording/readiness) → [физический мастер](http://192.168.0.168:8030/recording/check/tank) → [сбор датасета](http://192.168.0.168:8030/recording/collect). Базовый профиль — `tank_dock_rgbd_lidar`, 20 Hz. Реальные камеры могут быть медленнее: это показывает готовность и проверяет readback.

## Что обеспечивает программа

- Пределы на Pi: manual 0.2 м/с и 0.5 рад/с; остальные источники не выше
  0.3 м/с и 1 рад/с, абсолютный потолок 0.6/2. Штатный контроллер может
  дополнительно уменьшить команду; записывается фактически принятая скорость.
- Разгон ограничен 0.5 м/с² и 2 рад/с². STOP/отпускание/защиты дают нули
  сразу, без рампы. Native TTL 350 мс действует независимо от Wi-Fi.
- Лидар ±30° по направлению движения: 0.15 м, а при медленном подъезде
  ≤0.1 м/с — 0.05 м. Свободное обратное направление доступно. Это защита
  в плоскости сканирования, она не видит предметы ниже/выше луча.
- Наклон IMU >20° и напряжение <6.9 В останавливают движение. 7.2 В —
  предупреждение зарядки. Устаревшие IMU/scan запрещают ненулевые команды.
- Потеря USB/EIO завершает lease. Восстановление проверяет только три нулевые
  записи; продолжение требует подтверждения «Tank стоит» и нового включения.
  Прежняя команда не повторяется. Состояние переживает рестарт, но сам рестарт
  не открывает моторную плату. Частые отказы и минимум напряжения сохраняются.
- Gamepad/SBUS не передают управление штатному издателю во время сессии Explorer.

Если USB отсутствует, программный STOP физически не может дойти до платы.
`neutral_written` подтверждает запись в serial, не остановку гусениц. При
продолжающемся движении требуется выключатель — это остаётся аппаратной границей.

## Датчики, измерение и калибровка

RGB/depth/IR, scan, IMU, CameraInfo и доступное облако сохраняются прежними
наблюдателями. Пакеты дополнены буфером принятых IMU/scan с временными метками;
это не обещание получения всех опубликованных DDS-сообщений. Пропуски проверяются
по времени. У кадров явно указаны единицы и часы источника.

`observation.state` Tank по-прежнему предыдущая команда, не энкодеры.
`yaw_rate_imu` и `forward_displacement_lidar` — отдельные поля. Линейная оценка
по двум передним сканам отвергается при повороте, разрыве и плохом совпадении;
движущийся объект не отделён от собственного движения. Она не называется
калиброванной одометрией.

Прочитан установленный `odom_publisher_node.py`: `/odom_raw` интегрирует
`linear_x`, `angular_z`; коэффициент Tank 0.52. Энкодеров в этой цепочке нет.
`scripts/tank_calibration_report.py` сохраняет YAML и SHA только в runtime.
Исходные и installed YAML различаются; параметры не переписывались. Для R8
пользователь проезжает размеченный метр, накопленный поворот оценивается по IMU.
При отклонении >10° требуется физическая калибровка по официальной главе 3.2:
`ros2 launch calibration linear_calib.launch.py`,
`ros2 launch calibration angular_calib.launch.py`; IMU:
`ros2 run imu_calib do_calib --ros-args -r imu:=/ros_robot_controller/imu_raw --param output_file:=/home/ubuntu/ros2_ws/src/calibration/config/imu_calib.yaml`.
Эти команды могут двигать робот/требуют перестановок; агент их не запускал.

`scripts/tank_health.py` читает CPU, температуру, throttled, скорости потоков,
HTTP RTT и последнюю известную длительность serial-записи, не посылая пробную
команду. На штатном стеке камера местами ниже 10 кадров/с — это красный пункт,
не замаскированный PASS. Среди нагрузок найден штатный joystick_control (~ядро);
самостоятельно ненужные узлы не отключались. Проверка после пользовательской
передачи управления Explorer остаётся в R8.

## Передача управления

Штатный `~/.stop_ros.sh` содержит массовый `kill -9` по строкам процессов ROS.
Вместо его запуска используется адресный SIGINT проверенного bringup launch и
остановка его службы. `wifi.service` тоже открывает Board через SDK, поэтому
сохраняется её временное освобождение и возврат прежнего состояния. Настройки
NetworkManager/AP, производительские файлы и прошивка не изменяются.

# История настройки до R2

Модель по установленной конфигурации: MentorPi_Tank, Raspberry Pi 5, ROS 2 Humble в контейнере MentorPi. Передняя Aurora930 выдаёт RGB 640×400: проверено read-only через штатный web_video_server. Проект не использует старый backend для записи или управления. Свежий rclpy-процесс не обнаружил уже запущенные заводские DDS-узлы после переключения Wi-Fi; отдельная камера проекта с новым receiver ещё требует проверки при передаче ресурсов.

LeROS2 изучен по commit c8ca08b550a34db1a4e87edaad468f4ad829524a: factory компонентов и src не содержат адаптера Twist. Поэтому используется предусмотренный заданием небольшой адаптер над копией SDK и штатной формулой шасси. Исходный код LeROS2 не копируется в проект.

Собственный агент: /home/ubuntu/explorer3 внутри существующего MentorPi. Новая Python 3.10 venv; неизменяемые системные ROS/OpenCV зависимости используются через --system-site-packages, PYTHONNOUSERSITE=1. Новые FastAPI/uvicorn/serial и зависимости закреплены в configs/tank-agent-requirements.lock.txt. Бинарник камеры и SDK находятся только на устройстве и в закрытом локальном provenance, вне Git. Учебные данные, декодирование записи, LeRobotDataset, обучение и inference — на Homebrain.

## Управление и ресурсы

- Порт 8041; ограничение IP Homebrain/loopback плюс отдельный токен, хранимый вне Git. Служба explorer3-tank-agent.service установлена, активна, пока не enabled. Запуск инертный.
- Для открытия нужны разрешение физического блока C, handoff marker текущей загрузки, свежие камера/питание. Нет автоматического восстановления движения. Пока блок C не разрешён, POST /session возвращает 409.
- Передача временно останавливает ровно найденный заводской launch bringup через SIGINT, затем ранее активные start_node.service/wifi.service. Штатный board node при SIGINT отправляет нули. Host root проверяет владельцев /dev/ttyACM0 и USB до разрешения копии. Wi-Fi соединением управляет NetworkManager; остановка менеджера кнопки wifi.py не должна менять соединение. Это ещё нужно подтвердить в физическом блоке.
- Helper запускается отдельной временной systemd-службой: возврат продолжится при обрыве SSH во время штатного переподключения Wi-Fi.
- Возврат: STOP копии, освобождение SDK/камеры, удаление handoff marker, восстановление только ранее активных служб. Старые файлы не редактируются. Поведение штатного запуска и возврат телефона требуют физической проверки.
- Команды v, omega ограничены штатными ±0.2 m/s, ±0.5 rad/s. Первичные клавиши Explorer: ±0.1 m/s и ±0.3 rad/s. Знаки четырёх моторных каналов, геометрия и коррекция прямого хода сохранены из установленного контроллера; прочитанные left/right correction = 1.0.
- Локальный watchdog: TTL команд 350 ms, проверка каждые 20 ms; battery freshness 2 s, RGB freshness 500 ms. Новый старт даёт 500 ms до первой команды. STOP, просрочка, низкое питание, ошибки сенсоров разоружают сессию. HTTP принятие не является подтверждением MCU.
- Браузер: стрелки/WASD или экранные удерживаемые кнопки; отпускание — нулевая команда, пробел/STOP — закрытие; blur/hidden/pagehide/disconnect — остановка Tank. SO-101 по-прежнему допускает blur видимой вкладки, но останавливается при hidden. Смена робота сбрасывает удержания; активная сессия сначала закрывается.
- ExecStopPost имеет ограниченный fallback нулей только после фактического владения в текущей загрузке, а также закрывает только собственный экземпляр камеры. Аварийное завершение процесса пока не проверено физически.

## Данные и питание

Профиль tank_dock: целевой цикл 20 Hz, front RGB 640×400, action=[forward_velocity,yaw_velocity], units=[m/s,rad/s]. observation.state — две предыдущие отправленные команды, явно командная оценка. Энкодеры присутствуют в конструкции, но используемый SDK не предоставляет измеренные скорости/позиции колёс. Заводская odom интегрирует команды; она исключена из измеренного ответа. Реальные IMU/напряжение с возрастом сохраняются отдельно. Raw IMU пока без утверждения преобразованных единиц.

Часы Homebrain и Tank раздельны. Сохраняются ROS camera stamp, время получения агентом, время доступности на Homebrain, оба интервала отправки и факт принятия агентом. Midpoint/min-RTT оценка смещения записывается с ограничением; она не делает часы общей шкалой. Повторённый кадр отмечается. Нет выдуманного моторного acknowledgement.

[Hiwonder MentorPi T1](https://www.hiwonder.com/products/mentorpi-t1) указывает 7.4 V, 2200 mAh, 10C. [Getting Ready, 1.3](https://wiki.hiwonder.com/projects/MentorPi-T1/en/latest/docs/1.getting_ready.html) рекомендует заряд ниже 6.4 V. В фактически установленном ros_robot_controller_node.py Tank использует 0x1af4 = 6900 mV. Explorer останавливает ниже 6.9 V, не изменяя пороги MCU или батарею. Противоречащий generic SDK комментарий про 11 V не использован. Наклейка пользователем не прочитана; конфигурация модели и измерение согласуются с документированным штатным питанием. Проценты заряда не рассчитываются.

## Проверено и осталось

Проверено: Wi-Fi после снятия Ethernet; read-only заводская камера/напряжение/IMU; копии SDK и камеры с совпавшими SHA256; инертный restart агента; запрет неразрешённой сессии; HTTP UI; 13 программных тестов, включая ограничения, TTL, отпускание/смену робота. Визуальная проверка браузером недоступна в текущем окружении.

Не проверены: передача физических ресурсов, свежий собственный camera pipeline, клавиши на настоящем шасси, STOP/потеря связи, три записи и train/save/reload, возврат телефона. Эти пункты нельзя заменять программными тестами. Следующее действие пользователя — подготовить свободный участок пола и видимую цель с отмеченной зоной, закрыть управление на телефоне и разрешить блок C. Другие роботы не нужны; Ethernet уже снят и не требуется.

## Историческая запись после инцидента (заменена R0–R9)

Первая проверка движения завершилась физическим FAIL: STOP не остановил Tank по наблюдению пользователя. Описанный выше прямой SDK-адаптер заменён полной штатной цепочкой; старое описание и нейтральный probe являются историей подготовки, не подтверждением безопасности. Текущее устройство и ограничения описаны в TANK_INCIDENT.md и STATE.md. На тот момент движение было заблокировано до стендовой приёмки; это прежнее решение отменено текущим заданием R0–R9.

## Текущее управление (2026-11-13)

Оператор подтвердил движение, остановку при отпускании и STOP на штатных скоростях. Стендовый режим снят, история инцидента сохранена. В обычном интерфейсе Tank нужны только «Включить управление», восемь стрелок и STOP. Подключение ресурсов выполняется при явном запуске; открытие страницы не двигает робота. Возврат телефона находится в дополнительных настройках и называется «Вернуть управление приложению Hiwonder».

↖/↗ ведут вперёд по дуге, ↙/↘ — назад по дуге в выбранную сторону; W+A/W+D/S+A/S+D дают те же команды. При задержке видео ручное движение обнуляется, удержанные команды сбрасываются. После возвращения видео нужно отпустить и снова нажать стрелку. Потеря браузера/связи/питания закрывает сеанс; политика и replay также прекращаются при потере камеры.

Запись доступна через вкладку «Запись» и общий LeRobotDataset. Для Tank подготовлены replay/ACT через собственный агент и те же штатные ограничения; каждому испытанию нужно отдельное разрешение плана. Во время расчёта ACT удерживается нулевая скорость. Настоящие три подъезда, обучение на них, физический навык и возврат приложения телефона пока не приняты. Длительные нулевые проверки транспорта не являются демонстрациями задачи.

Проверка нового ручного конвейера:1300нулевых отсчётов и613уникальныхRGB за69.91с, без закрытия сессии и ошибок освобождения ресурсов. Поведение камеры не объявляется бесперебойным: пауза делает движение нулевым и требует нового ввода.

**Найдено несоответствие поставки исходников:** официальный GitHub redirect ведёт на `Hiwonder/MentorPi-ROS`; default branch — M1, поэтому она не подходит. Если он неполон, производитель предлагает запрос полного образа/исходников с номером заказа; письмо самостоятельно не отправлялось.

Документация содержит фрагменты, перенесённые из других шасси (например, слово Ackermann рядом с `MentorPi_Tank`). Поэтому исходные параметры сверяются с фактически установленной веткой и моделью. Пропадание USB и невозможность доставить STOP остаются отдельным незакрытым аппаратным инцидентом; найденные инструкции не доказывают его устранение и не дают подтверждения motor TTL в MCU.
